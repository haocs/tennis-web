# UI copy

Keep the website clean and intuitive. Add visible text only when it helps a user identify content or an action, understand a meaningful consequence, or recover from a problem.

- Prefer clear labels and self-explanatory controls over explanatory paragraphs.
- Do not add taglines, decorative headings, redundant summaries, developer commentary, or implementation details to the UI. Keep technical explanations in repository documentation.
- Do not repeat information already shown by a heading, button, selected step, or status.
- Keep essential instructions, errors, empty states, units, and external-sharing disclosures brief and close to the relevant action. Put occasional help behind a clearly named disclosure when useful.
- Preserve accessible names, field labels, focus behavior, and screen-reader context when removing visible copy.
- Review both mobile and desktop layouts after changing UI copy; remove leftover empty spacing.
